# Chromebookでの手書き試用

対象として共有された機種はLenovo 500e Chromebook Gen 4s (Light) 11.6型 Intel。
実際のMTM・ペン名称・ChromeOS版は未確認で、Chromebook実機での検証は行っていない。
シリーズ名だけでタッチ対応構成や付属ペンを確定しない。

## 入力と操作

- 小テストを開いた直後、再読込後、別課題への移動後は、ペン・消しゴムとも未選択。過去の筆跡の復元はツールの選択状態から分離する。
- 未選択では、指・認識済みpen・マウスのいずれも書かず、消さない。指1本のスクロールとブラウザーのnative pinchは従来どおり使える。
- 「ペン」を選ぶと指1本・touch扱いのペン・認識済みpen・マウスで書く。「消しゴム」を選ぶと同じ入力で消す。選択中のボタンをもう一度押すと未選択へ戻る。新しいボタンは追加しない。
- 選択中は2本で紙面を移動し、指の間隔でPDFを拡大縮小する。倍率は幅に合わせた表示から3倍まで。紙面内だけアプリがジェスチャーを処理し、紙面外やブラウザーの拡大操作は変更しない。
- 選択中は手のひらを画面から離す。`touch`として届くペン・指・掌をWeb側で確実に区別することはできない。掌が加われば2本指操作として扱われ、筆記が取り消されたり紙面が動く可能性がある。
- 2本以上の操作後や接触中のツール切替後は、すべて離してから書き始める。3本以上では操作を中断し、全接触の解放を待つ。
- 端末・OSがペンの接触自体を通知しない場合、アプリの修正だけでは筆記できない。

## 答案を保護する仕組み

ツール選択中のtouchの1画は接触中だけの仮筆跡として描画し、確定済み操作の配列には入れない。
1本のまま離したときに確定し、自動保存へ通知する。
途中で2本目が触れた場合、今回の仮筆跡だけを破棄し、移動・拡縮に切り替える。
消しゴムの仮操作も同じで、以前に確定した筆跡や消去は巻き戻さない。
保存中にtouchが加わっても、保存要求・PDFスナップショットには仮操作が入らない。
紙面に接触が残る間は提出を開始せず、指やペンを離す案内を表示する。

touchの未確定の1画は、cancel・捕捉喪失・タブ非表示・画面再描画・ツール変更でも取り消す。
これを確定済み答案の消失と混同しない。認識済みpenとマウスでは従来どおり途中までの筆跡を保持する。
ポインター捕捉が失敗した場合やタブが非表示になった場合も状態を解放し、次の筆記を可能にする。

保存形式はPDF座標を使う既存形式を維持する。画面倍率・回転・DPRは表示に適用し、保存座標に重ねて掛けない。
選択中の紙面は`touch-action: none`、未選択では従来の`pinch-zoom`にする。ツール操作で接触開始前に設定し、接触中に切り替えた場合は入力を終了して全接触の解放を待つ。独自の移動処理とnative pinchを同時に処理しない。
確定済みの描画キャッシュと仮描画を分離し、ジェスチャー終了後に既存のメモリー上限内で再描画する。

## 検証範囲

Nodeの合成イベント、Chrome WebDriver/CDPからのtouch入力、専用PostgreSQLクラスタの架空データで検証する。
これらはChrome上の処理の確認であり、実機のペン認識・書き心地・遅延・掌除去・学校の端末管理ポリシーを保証しない。
実生徒データ・実AI呼び出しは使わない。

ゲストは閲覧専用で、手書き画面・下書き・提出経路が許可対象外。
通常版の入力機能をゲストの旧baseへ一括適用せず、既存の隔離・閲覧専用ポリシーを維持する。

## 学校での短い確認手順

先生が用意した架空の試用課題で、次を確認する。

1. 実際の機種型番、ペン名称、ChromeOS/Chrome版を控える。ペンの充電等を確認する。
2. 最初は両ツールが未選択で、指で移動・拡縮でき、ペンやマウスでも描画されないことを確認する。「ペン」を選び、掌を浮かせ、点を10個、数字・曲線・短い線を書く。指1本でも筆記になることを確認する。
3. 2本で上下に移動し、間隔を広げて拡大・狭めて縮小する。置き始めの仮線や仮消去が残らず、以前の答案が残ることを確認する。
4. 2本から1本だけ離した間は線が出ず、全部離した後で再び書けることを確認する。ペン・消しゴムでも試す。
5. 縦横回転・タブ切替後に書けること、確定済みの線がずれないことを確認する。中断時のtouchの未確定1画は取り消される。
6. 選択中のボタンの再押下で未選択へ戻り、以後は描画されないことを確認する。「保存済み」後に再読込し、筆跡・消去が復元されてもツールは未選択であることを確認する。別課題も未選択で開くことを確認する。
7. 架空課題を提出し、教師側の答案PDFでも線・点・消去・複数ページが一致することを確認する。実AI採点は今回のコード検証には含まれない。

入力が届かない場合は、紙面外でもペンが反応するかを学校側で確認し、型番・ペン名称・OS/Chrome版と再現手順を記録する。
既存の`#pdf-input-diagnostics`は任意の開発者診断で、イベント受信と状態を画面内メモリーだけに記録する。答案内容・座標・秘密設定は記録しない。
