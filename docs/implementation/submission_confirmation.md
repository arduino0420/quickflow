# 生徒の提出前確認（#160）

手書きと従来アップロードの正式提出入口に、共通の HTML `dialog` で「提出しますか？」「いいえ」「はい」を表示する。初期フォーカスは「いいえ」。Esc・閉じる・背景クリックも取消として扱う。

```
解答中 → 確認中 → 取消 → 解答中
               → はい → 現在状態の再確認 → 既存の提出処理
```

- 確認を開く前に手書きの最終ストロークを終端する。確認中は背景入力を止めるが、通常の下書き自動保存は止めない。取消で筆跡・ツール・倍率を変更せず、提出ボタンのフォーカスと確認開始時のスクロール位置を復帰する。
- 取消では提出状態 GET、提出用 PDF 生成、正式 POST を開始しない。下書き保存の通信とは区別する。
- 手書きの「はい」は current session・編集可能状態を再確認した後、従来の提出本体に進む。元の token / revision / draft_version / 教材照合・POST 応答消失時の同一 attempt 照合を保持する。容量上限時に従来許可される提出経路も保持する。
- 従来アップロードは「はい」の後に認証付き・キャッシュなしの元画面 GET を行い、現在の未提出フォームの署名付き生徒・課題・教材 context と選択 PDF の同一性を確認してから従来フォームを送る。失効・教材差替え・別タブ提出・通信不明では送らない。pagehide / disconnect は旧確認を無効にし、未完了の GET を中断する。
- 送信中の連打は受け付けない。サーバーの認可・CSRF・提出一意性・添付検証・ジョブ登録は変更しない。ゲストには提出入口を追加しない。
- JavaScript が使えない場合、従来フォームの送信ボタンは初期 disabled のままとし、確認を省略するフォールバックは設けない。
- DOM のダイアログを破棄した Controller は参照も破棄し、再接続時に新しい確認を作る。確認後に古い session の非同期結果から送信しない。

## 検証の境界

隔離 PostgreSQL・架空 PDF と API スタブで確認する。JavaScript 仕様は取消の通信ゼロ、単一確認、古い session / 切断 / pagehide、選択 PDF / context の変更、同一 attempt による応答消失復旧を扱う。ブラウザ仕様は取消前後の筆跡・自動保存・フォーカス、Yes 後の既存提出、従来アップロード、狭幅・横向き・文字拡大・合成タッチ・アクセシビリティツリーを確認する。

実機タッチ端末・ペン・実スクリーンリーダー・全ブラウザの確認を意味しない。実 AI 通信、本番の答案提出、デプロイは本件のローカル検証には含めない。
