# Issue #50: 検証責務と現行互換性

## 対象と結論

[Issue #50](https://github.com/arduino0420/quickflow/issues/50) の旧監査時点は `984fe922`。本表は [main@6cc75b2](https://github.com/arduino0420/quickflow/tree/6cc75b2909eb51679df8a230baf72c5a485b912f) の実装を根拠とする。以下の相対リンクはリポジトリ内の現行ソースを指す。

DBは保存経路を問わないNOT NULL・一意性・参照先の存在、Modelは通常のActive Record保存時の属性・関連検証、Service/Controller/Jobは入力形式・AI応答・利用時の集合・ワークフローを受け持つ。ModelとDBは完全同一ではない。DBのNOT NULLは空文字を拒否せず、FKは学校や課題の一致を保証しない。モデルのuniquenessだけでは競合を防げないため、一意indexとの併用は必要な重複である。

**今回は文書のみ。検証の移動・追加、列削除、JSON変換、constraint追加、新CRUDは不要と判断する。** NULLや通常テキストの `Question.grading_rule` を許す保存契約と、AI採点で使える構造の契約は異なる。後者をモデルに移すと既存互換性が変わる。横断整合性の変更は #43、全validation/association/enum/scopeの網羅テスト追加は #98、#93 / PR #110・#94 は別タスクであり本変更に含めない。
