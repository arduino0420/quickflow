# 教師の小テスト登録は、どう動く？

<div class="intro"><p>今回の機能は、<strong>ログイン中の教師が入力した小テストを、その教師のものとして保存する処理</strong>です。</p><p>Rails学習中のあなたが自分で説明できるよう、画面表示→入力の受け取り→保存の順につなげます。学習中という点は依頼文から、コードと動作を並べると理解しやすいという点は説明方法として仮定しています。</p><nav aria-label="解説の目次"><a href="#step1">1. routes</a><a href="#step2">2. ログイン確認</a><a href="#step3">3. new</a><a href="#step4">4. form_with</a><a href="#step5">5. createとparams</a><a href="#step6">6. 添付</a><a href="#step7">7. 303と422</a><a href="#step8">8. テスト</a><a href="#flow">保存までの一本道</a></nav></div><section id="step1"><h2><span>1</span>routesは「どの処理へ渡すか」を決める</h2><p><code>config/routes.rb</code>の次の行は、登録に必要な2つの入口を作ります。</p><pre><code>resources :assignments, only: [ :new, :create ]</code></pre><div class="table-wrap"><table><thead><tr><th>ブラウザからのアクセス</th><th>呼ばれる処理</th><th>目的</th></tr></thead><tbody><tr><td>GET /assignments/new</td><td>new</td><td>登録画面を開く</td></tr><tr><td>POST /assignments</td><td>create</td><td>入力内容を登録する</td></tr></tbody></table></div><p><code>resources</code>は、Railsの決まった命名に沿ってURLとControllerを結びつける書き方です。<code>only</code>で今回必要な処理だけに限定しています。</p></section><section id="step2"><h2><span>2</span>before_actionは「処理の前に教師か確認する」</h2><p><code>AssignmentsController</code>では、画面表示や登録より先に次を実行します。</p><pre><code>before_action :require_teacher_login</code></pre><p><code>require_teacher_login</code>は、<code>current_teacher</code>が取得できなければ<code>/login</code>へ戻します。リダイレクトした場合、<code>new</code>や<code>create</code>には進みません。</p><p><code>current_teacher</code>は、sessionに記録された教師IDから教師を探す既存の処理です。未ログインや生徒ログインでは教師が取得できないため、登録できません。</p></section><section id="step3"><h2><span>3</span>newは「フォームに渡す空の小テストを用意する」</h2><pre><code>def new
  @assignment = current_teacher.assignments.build
end</code></pre><p><code>current_teacher.assignments</code>は「ログイン中の教師に属する小テスト」です。その関連から<code>build</code>することで、教師IDが設定された新しいAssignmentを作れます。</p><p class="note"><strong>buildの時点ではDBに保存されません。</strong> <code>@assignment</code>は、フォームに渡すための未保存のRubyオブジェクトです。<code>@</code>が付く変数はViewからも使えます。</p><p><code>new</code>には明示的な<code>render</code>がありませんが、Railsが対応する<code>assignments/new.html.erb</code>を表示します。</p></section><section id="step4"><h2><span>4</span>form_withは「入力欄と送信先を作る」</h2><p>登録フォームでは、用意したAssignmentをフォームに渡します。</p><pre><code>&lt;%= form_with model: @assignment do |form| %&gt;</code></pre><p>Railsは未保存のAssignmentだと判断し、POST <code>/assignments</code>へ送信するフォームを作ります。入力は次の形でControllerに届きます。</p><pre><code>params[:assignment][:title]
params[:assignment][:point_per_question]
params[:assignment][:material_file]</code></pre><p><code>file_field</code>があるため、ファイルも送れる形式のフォームになります。点数欄の<code>min: 1</code>・<code>step: 1</code>はブラウザ側の入力補助で、保存できる値かどうかはモデルでも確認します。</p></section><section id="step5"><h2><span>5</span>createは「許可した入力で小テストを作り、保存する」</h2><pre><code>@assignment = current_teacher.assignments.build(assignment_params)</code></pre><p>ここでは、空の小テストではなく、送信された入力を入れた小テストを組み立てます。</p><p>ただし、ブラウザから送られた値をすべて使うわけではありません。<code>assignment_params</code>で受け取る項目を絞ります。</p><pre><code>params.require(:assignment).permit(:title, :point_per_question, :material_file)</code></pre><p>つまり、「<code>assignment</code>というまとまりから、この3項目だけを採用する」という処理です。この仕組みを<strong>Strong Parameters</strong>と呼びます。</p><p><code>teacher_id</code>は許可せず、教師との関連から<code>build</code>します。この2つを組み合わせることで、別の教師IDを送っても、登録先はログイン中の教師になります。</p><p class="note">Strong Parametersは「受け取ってよい項目」の確認です。「タイトルが空ではないか」などの値の確認はモデルの役割です。</p></section><section id="step6"><h2><span>6</span>material_fileは「添付をRailsの保存機能へ渡す」</h2><p>既存Assignmentモデルには次があります。</p><pre><code>has_one_attached :material_file</code></pre><p>これは、Assignmentに1つの教材ファイルを添付できるという宣言です。フォームから届いたファイルを<code>build</code>に渡すと、Railsの添付管理機能である<strong>Active Storage</strong>が保存処理を担当します。</p><p>DBにはファイル情報とAssignmentとの紐づけが保存され、ファイル本体は設定された保存先へ置かれます。今回は添付なしでも登録でき、PDF限定にはしていません。</p></section><section id="step7"><h2><span>7</span>saveの結果で、303と422に分かれる</h2><p><code>@assignment.save</code>は、モデルの入力チェックを実行し、問題がなければ保存します。</p><div class="table-wrap"><table><thead><tr><th>結果</th><th>Controllerの処理</th><th>ブラウザで起きること</th></tr></thead><tbody><tr><td>成功</td><td><code>redirect_to ... status: :see_other</code></td><td>HTTP 303で登録画面をGETし直す</td></tr><tr><td>入力エラー</td><td><code>render :new, status: :unprocessable_entity</code></td><td>HTTP 422でエラー付きフォームを表示</td></tr></tbody></table></div><p>成功時は、新しいGETで<code>new</code>が実行されるため、空のフォームになります。成功メッセージは次の画面へ引き継ぐ<code>flash[:notice]</code>で表示します。</p><p class="note">失敗時の<code>render :new</code>は、<strong>newメソッドを実行する命令ではありません。</strong> 入力値とエラーを持った現在の<code>@assignment</code>で、同じViewを描き直します。添付ファイルは引き継がず、再選択が必要です。</p></section><section id="step8"><h2><span>8</span>assignments_spec.rbが確認していること</h2><p><code>spec/requests/assignments_spec.rb</code>のrequest specは、実際のログイン処理を使い、GET・POSTから保存と応答までを確認しています。</p><ul><li>教師には正しいフォームが表示される。</li><li>登録するとログイン中の教師に紐づく。</li><li>添付なし・PDF・非PDFで登録できる。</li><li>不正な入力では保存せず、422で入力値とエラーを表示する。</li><li>失敗した添付を保存・引き継ぎしない。</li><li>未ログイン・生徒ログインでは表示と登録を拒否する。</li><li>教師ID・公開日時・配信先を送っても、許可していない値は設定されない。</li><li>成功時は303で戻り、成功メッセージと空のフォームを表示する。</li></ul><p>前回の実行では15件すべて成功しています。ただし、実ブラウザでの見た目や操作までを保証するテストではありません。</p></section><div class="recap"><h2>自分の言葉で説明してみる</h2><p>自分で説明するときは、次の3点を言えれば中心を押さえられています。</p><div class="table-wrap"><table><thead><tr><th>問い</th><th>答え</th></tr></thead><tbody><tr><td>buildは何をする？</td><td>教師に紐づいた未保存の小テストを作る。</td></tr><tr><td>assignment_paramsは何をする？</td><td>採用する入力項目を3つに絞る。</td></tr><tr><td>失敗時になぜrenderする？</td><td>入力値とエラーを持つオブジェクトでフォームを描き直す。</td></tr></tbody></table></div></div><section id="flow"><h2>画面を開いてから、保存されるまで</h2><p>最後に、<strong>ブラウザで画面を開いてからDBへ保存されるまで</strong>を一本道で並べると、こうなります。</p><ol class="flow"><li>ブラウザで GET /assignments/new</li><li>routesがnewへ渡す</li><li>before_actionで教師ログインを確認</li><li>current_teacher.assignments.buildで空の小テストを用意</li><li>new.html.erbのform_withでフォームを表示</li><li>教師が入力し、登録ボタンを押す</li><li>ブラウザから POST /assignments</li><li>routesがcreateへ渡す</li><li>before_actionで教師ログインを再確認</li><li>assignment_paramsで3項目だけを採用</li><li>current_teacher.assignments.buildで入力を入れ、教師に紐づける</li><li>saveでモデルの入力チェック</li><li>問題がなければDBへ保存し、添付はActive Storageが保存</li><li>HTTP 303で登録画面へ戻り、成功メッセージを表示</li></ol></section>

<p>この解説は実際のコードを読み直して作成した内容です。先ほどの解説時には、コード変更やテストの再実行は行っていません。</p>
